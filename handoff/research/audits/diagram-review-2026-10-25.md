## What each sponsor contribution means

- **SpacetimeDB:** core realtime state, subscriptions, transactional reducers and worker coordination. Show reducer writes, committed row updates, audience views and the bridge's pending-command subscription separately. The [official prize card](https://hive.hackberkeley.org/prizes) and [sponsor announcement](https://spacetimedb.com/blog/spacetime-at-calhacks) support this story; neither requires a minimum number of AI agents. Private views do not make public raw tables private. The [complete view inventory](../../../diagrams/views.md) distinguishes role/identity filtering from client query choices.
- **Elastic:** the strongest contribution is scoped policy retrieval, semantic ranking, checked page citations, ES|QL-backed precedent proposals and bounded investigation. Fixed prompts also gain workflow execution and audit records. Moving a prompt does not establish higher quality, lower cost or greater autonomy. The [sponsor workshop](https://github.com/jdarmada/calhacks-paper-scout/blob/main/slides/deck.html), linked by its presenter in the saved sponsor research, covers search, Jina, Agent Builder, Workflows and Serverless. Claude can remain the underlying model behind Elastic; it is not a separate direct worker path.
- **Bright Data:** server workers discover event and policy sources through [Web MCP](https://docs.brightdata.com/products/mcp-server/tools), retrieve raw documents through [Web Unlocker](https://docs.brightdata.com/products/web-unlocker/introduction), and export interactive venue maps through [Browser API](https://docs.brightdata.com/products/scraping-browser/introduction). The official prize brief requires useful live public data and a working user flow. The organizer queues event preparation through the application; server workers perform the import. The implementation is deployed in `ec63ce0`; one real queued import completed on its first attempt, with fresh Bright Data source acquisition and Elastic organization. Existing venue discovery/map setup is a separate implemented organizer flow. The venue laptop handles the physical bridge and security cameras, not event preparation.
- **Meta:** show event-grounded candidates, semantic interest ranking, shared memories and reconnection. The [published rubric](https://hive.hackberkeley.org/prizes) asks for meaningful connection and integrated AI; it does not name a required Meta API or model. Photo names come from band/time candidates, not face recognition. Sharing a file and @handles through the phone share sheet is not automatic Instagram publishing or API photo tagging.
- **Capital One Nessie:** show completed account, purchase and injury-deposit operations and their returned references. The [official API](https://nessieisreal.com/docs) exposes distinct financial resources. Property settlement is booked to the venue/repair vendor; it is not an external Nessie transfer. Organizer-recorded venue-insurer receipts are reconciled by code, not automatically collected from an insurer.
- **Hyphenate:** preserve precedents → proposed rule → human approval → future code-guarded settlement. Policy clauses determine coverage; precedents teach bounded payment authority. The [official brief](https://docs.google.com/document/d/1u4iN8R97ILY3kfHTPKC82zdutHrGx4ze5eCAP-J92w4/edit) and saved workshop deck emphasize enforced limits, durable history and accountable approvals. Diagnosis-specific rules are not a stated requirement.
- **Vultr:** the deployed VM, Caddy and running Rust services are the actual contribution. External database and model services remain outside that host. The [MLH partner page](https://www.mlh.com/partners/vultr) includes virtual machines; GPU hosting is not required.

The compact board separates queue coordination from model execution, retrieval from approval, shopping from payment transport, and live writes from audience subscriptions. Workers call Elastic and validate results; Elastic does not directly write application tables. The investigation agent requests clause searches that the worker executes. The original hardware board is retained unchanged and only its new hardware frames are combined.

Minutes together and per booth match current code and remain by Viktor's explicit decision. Photo tagging has no fixed 20-tag ceiling after the deployed correction. The model-output limit and initial provisional tags are different controls. Social sharing labels say @handles; model inputs for merchandise are captions and tags, not photo pixels.

Claims now have separate settlement, amount derivation and reusable-rule frames. Medical eligible lines are capped by fee-schedule amount multiplied by service units. Excess medical cover with an available plan copay uses the smaller of copay and covered bill; otherwise it uses the covered bill. Property basis is the logged repair/replacement cost. Payout is the minimum of eligible basis, per-claim limit and remaining aggregate. The deductible reduces insurer recovery, not the settlement payout. Charges follow a separate organizer-approval and attendee-payment path, and approval requires an already-decided claim.

The published, verified Policy amounts inset illustrates the unchanged calculation with $895 Covered care and a checked $55 Plan copay. Assuming excess cover and both payout limits at least $55, it yields $840 Health-plan share and $55 Venue-cover payout under a calculated-split title. These are calculated allocations, not confirmation of an external plan payment. The inset is part of Policy amounts, not a new diagram; its canonical Plus update and public checkpoint both passed readback verification.

Generated reusable rules currently cover the incident kind, cover kind and all event zones, require corroboration, and have a ceiling equal to the highest cited payout within policy limits. The matcher can represent a zone-specific rule, but the current proposal-approval flow does not offer a zone picker. Diagnosis or treatment prose is not executable scope. Older narrower-looking wording requires explicit displayed-scope approval before the replacement can confer authority.

Catalog checkout is intentionally available during and after the event under the latest user decision, reflected in `530820a` and `8b63c89`. Personalized recommendations still begin at departure or event end. This distinction is not a missing checkout guard.

Typed friend search and automatic interest suggestions are separate. The search first requires the requester's recorded, findable encounter candidates. A named booth requires overlapping visits to that same booth; a meeting's initial zone alone supports zone evidence. Code resolves named places and produces reasons. Elastic reranks eligible transient evidence in bounded batches. Similar interests are never used as proof that two people met.
