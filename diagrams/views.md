## Diagram 23 scope

## Access rules that affect the drawing

- `viewed(ctx)` means caller or target set by an owner-created fresh View-as identity. `my_owner`, `board_staff`, `view_as_people`, and `worker_jobs` use the real sender.
- Most board views allow **ops or medic or owner**. Claim-ID detail views permit **ops or owner** only. Merch order/shipping and wallet boards are also ops/owner.
- `medic_medical_cards` returns cards tied to granted access logs for the viewed reader. The granting reducer checks medic/owner, but the view does not recheck current role, require an open incident, or expire the grant.
- Service views have different permissions: attendee/visit/encounter/shared-visit rows allow api/indexer/worker; sessions, handles, photos and tags allow api only. Owners also pass. Actual workers currently subscribe only to `worker_jobs`.
- `worker_jobs` exposes all open jobs to worker/owner identities, not only the caller’s leases. Result reducers enforce the live lease separately.
- Anonymous projections are `claimed_people`, `event_graph`, and `venue_plan`. The frontend also subscribes directly to public venue, zone, band, booth and command tables. These are separate from filtered views.
- Raw public `departure`, `band_place`, `incident_marker` and `decision` tables also exist. Filtered views do not make public sources private.
- Nine staff RawQuery views and `board_staff` use `WHERE id = 0` for denied identities. This inventory records that exact sentinel rather than claiming a literal false predicate.

## Delivery and usage notes

- React `frontend/src/stdb/session.ts` requests attendee views independently and staff/desk queries one at a time. Its comments record past non-completing subscriptions and deliberately omit several full-board views. No live delivery was retested here.
- React now serves organizer `/payments`, attendee `/wallet` and venue setup `/venue`. Its payment screens add five staff queries (`board_charges`, `board_merch_orders`, `board_wallets`, `board_fee_schedule`, `board_merch_picks`) and four attendee queries (`my_wallet_entries`, `my_charges`, `my_merch_suggestions`, `my_merch_orders`). Server row scopes are unchanged.
- The shared React connection requests these attendee and staff lists independently of the current page route. This is not a claim that every device subscribes to the minimum possible data. Table-change callbacks still coalesce into a UI refresh after 200 ms.
- React venue setup separately subscribes to the public `venue_setup`, `venue_setup_step` and `chosen_venue` tables on every connection. These are raw tables, not three additional views.
- React puts `social_photos` in DESK_QUERIES, even though the server requires api/owner. That client-side list does not grant access.
- The plain organizer page subscribes to the larger board set; the band page subscribes to attendee rows. These are separate clients from the React desk.
- The only production parameterized detail subscription found is organizer `claim_clauses(claim_id)`. Other parameterized views are declared but no production query was found.
- `venue_plan` is declared but has no production subscriber found. `event_graph` is used by both desks; `claimed_people` by the band page. Do not draw all three as proven live feeds to one screen.
