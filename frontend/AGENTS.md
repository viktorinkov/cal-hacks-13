# Frontend writing

- Use short labels and one short sentence for instructions and empty states.
- Remove decorative summaries that repeat nearby counts, tables, status chips or headings.
- Write for any venue and event time. Read event names and locations from configured data.
- Keep recorded venue examples labeled as replays. Do not present them as the current event.
- Show real names, amounts and recommendation reasons. Omit missing descriptions instead of inventing them.
- Derive production application state from backend data. Do not fill missing state with fake people, counts, medical details or evidence. Recorded camera clips must be labeled; test fixtures belong in tests.
- Distinguish loading, unavailable data and an empty result. Unknown data must not look like a successful zero.
- State the action and its result. Keep financial approval, payment and receipt as separate steps.
- Name the task, not the underlying provider, unless that name helps the user act.
- Preserve actionable alerts, permissions, failure details and existing features when shortening copy.
- Keep navigation labels and order consistent across screens for the same role.
